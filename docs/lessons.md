# 可复用经验

## 连接与调用

1. 使用 Windows PowerShell（powershell.exe，.NET Framework），当前 PowerShell 7 环境没有 Marshal.GetActiveObject。
2. GetActiveObject("SldWorks.Application") 连接现有实例。沙箱内曾返回 0x800401E3；沙箱外成功取得对象。这是本机实测结果，并不代表所有连接失败都由沙箱造成。
3. 动态调用 RevisionNumber 曾返回 0x8002802B；加载本机 SolidWorks.Interop.sldworks.dll，通过 C# ISldWorks 强类型接口后成功。后续优先沿用这一方式。
4. C# 使用 System.Environment 全名，避免与 SolidWorks.Interop.sldworks.Environment 重名。
5. 不擅自结束进程、关闭用户文档或覆盖用户模型。优先创建独立测试零件。

## 原生建模

- 用户期望直接调用 API 创建可编辑特征树。外部生成 STEP 再导入不能替代这个实验目标。
- API 长度使用米，体积使用立方米。毫米输入除以 1000；体积转 mm³ 乘以 1e9。
- 避免通过本地化名称选择基准面。空白标准零件可遍历 FirstFeature / GetNextFeature，查找 RefPlane，再使用对象 Select2。首个 RefPlane 为前视面的假设仅适用于当前标准新零件模板。
- 当前近似模型用两个平面内的封闭 3D 草图作为前后截面，再调用 InsertProtrusionBlend2。放样截面选择标记为 1。
- 保持截面顶点数量和绕行顺序一致；检查连接是否扭转、对应面是否符合预期。封闭放样成功本身不证明几何推理正确。
- 目前草图坐标由脚本给定，未完成尺寸驱动与完全约束，不宜直接作为成熟参数化模板。

## 验证闭环

执行特征后检查返回值，重建，再检查实体数量和质量属性。长方体可用解析体积校验；复杂模型还应检查面类型、关键顶点和包围盒。

保存时检查 SaveAs 的布尔值和错误码；记录警告。用模型导出的 BMP 查看实际外观，不把 API 返回成功等同于视觉正确。当前脚本尚未完整记录特征重建错误、警告以及面平面性，后续应补齐。

“实时看状态”是主动查询或抓取视图：不是持续视频监视，也不能自动看到所有弹窗。需要时逐步执行、查询与检查图像。

## 三视图重建仍需验证

当前取宽 100、高 80、深 60 mm。前截面顶点（x, 高度，mm）：
(0,0)、(100,0)、(100,80)、(80,80)、(50,32)、(0,32)。
后截面：
(0,0)、(100,0)、(100,80)、(36,80)、(26,64)、(0,64)。

这些坐标是按照片估算的假设，不是测量结论。下一步应导出前、上、侧三视图，逐条比较轮廓和内部交线，再调整截面顶点。照片有透视变形，允许尺寸近似，但连接关系仍需核对。

## 失败尝试

旧 VBA 在按名称选择前视面时失败，后来改为特征对象选择，但修订版 VBA 未独立验证成功。旧宏中的拉伸实际是单向，原来的中面拉伸注释有误。

外部手写 STEP 两次 LoadFile4 均失败（错误码 1）。具体根因没有查明，不应当作已知格式修复案例；该路线已按用户要求停止并归档。

## 用户后续明确的偏好与批量经验

建模方法不限于拉伸或切除，以几何正确和可编辑为准。简单零件用“零件1”等中文文件名，草图及特征保留 SolidWorks 默认中文名称，不强制使用英文语义名称。demo 风格观察是参考，不是建模方法限制。

对称截面和非平行截面放样应明确顶点对应关系；本批采用逐顶点直线导引线，修复了自动对齐导致的扭转。实体合法且体积为正不能证明几何正确，必须查看预览。

SaveAs 导出 STEP 前明确用完整原生文件路径激活目标文档。回读检查采用唯一临时文件名并重命名导入文档，避免同名原生/导入文档混淆；只关闭本次创建的文档，不按通配名称清理用户未保存文件。
