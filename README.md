# SolidWorks API 自动建模实验与参考成果

本项目记录了一次从三视图理解几何、通过 SolidWorks API 建立原生实体、导出 STEP 并检查结果的实验。输入为教学课件《平面立体(2)》，主要包含由平面组成的基础立体、台阶、槽、斜面和截切体。

**最终交付为“零件1”～“零件20”，每件均有原生 SLDPRT、STEP 和多视图预览。** 模型通过本机 SolidWorks 2025 SP2 实际运行生成，原生文件保留草图、放样和切除等可编辑特征。

这里的自动化指“用脚本执行已确定的建模步骤”：课件图形由 AI 分析并写成坐标与特征调用，当前脚本包含这批题目的具体几何定义，**不是能直接读取任意 PPT 并自动建模的通用程序**。

## 实际验证了什么

| 项目 | 本机验证结果 |
|---|---|
| COM 连接 | 连接已启动的 SolidWorks，读到版本号 `33.2.0` |
| 基础建模 | 创建 100 × 80 × 60 mm 长方体；单实体、体积 480,000 mm³ |
| 课件建模 | 20 个编号零件均创建成功，保留原生特征树 |
| 原生模型检查 | 重建后检查单实体、正体积和特征错误码 |
| 文件保存 | 检查 SLDPRT 保存返回值及错误码 |
| STEP 导出 | 检查导出结果，回读后比较实体数量与体积 |
| 保存内容复核 | 只读重新打开 20 个原生文件副本，检查实体、体积及特征状态；全部通过 |
| 外观检查 | 导出并查看模型视图，修复了仅靠实体检查未能发现的放样扭转 |

STEP 回读和原生文件复核采用体积容差：`max(0.1 mm³, 原模型体积 × 0.001%)`。这个容差用于检查文件转换及保存一致性，并不代表模型相对原题的尺寸精度。

## 如何在另一台电脑复现

### 运行环境

本次使用 Windows、已安装并可正常使用的 SolidWorks 2025 SP2，以及 **Windows PowerShell（`powershell.exe`，基于 .NET Framework）**。脚本借助 `Add-Type` 编译 C#，加载 SolidWorks 自带的接口库，通过强类型 COM 接口调用。

运行这批建模脚本不需要安装 Python、MCP 服务或额外的 AI SDK，也不需要 Codex 持续参与。课件页面导出脚本需要 PowerPoint；重新建模本身不需要再次读取 PPT。PowerShell 7 的 `pwsh.exe` 未作为当前运行入口验证。

先修改需要运行的 `.ps1` 文件中 `$interop` 的路径，使其指向本机的 `SolidWorks.Interop.sldworks.dll`。本机验证时使用：

```text
D:\Programs\SolidWorks\SOLIDWORKS Corp\SOLIDWORKS\api\redist\SolidWorks.Interop.sldworks.dll
```

项目移动到其他文件夹后，当前批量入口通过 `$PSScriptRoot` 定位项目和输出，无需修改项目盘符。历史脚本可能仍含原电脑的绝对路径，不能据此假定所有早期脚本均可直接迁移。`Read-AllPages.ps1` 原先在根目录查找 PPT；当前课件已位于 `deliverables/`，如需重新导出页面，应先调整该脚本的输入路径。

### 推荐步骤

1. 启动 SolidWorks，确认默认零件模板已配置，关闭阻塞操作的模态对话框。
2. 在项目根目录打开终端，先运行只读连接测试。
3. 按需重建全部模型或指定编号；需要保留手工改动时，先备份相应成果文件。
4. 查看终端最终状态、检查记录和预览，再运行保存文件复核。

```powershell
# 连接测试
powershell.exe -NoProfile -File .\scripts\Test-SolidWorks.ps1

# 重建全部 20 个编号模型
powershell.exe -NoProfile -File .\scripts\Run-BatchModels.ps1

# 或仅重建指定编号
powershell.exe -NoProfile -File .\scripts\Run-BatchModels.ps1 -Ids '13,19,20'

# 只读复核已保存的 20 个原生文件副本
powershell.exe -NoProfile -File .\scripts\Inspect-Deliverables.ps1

# 更新总览图
powershell.exe -NoProfile -File .\scripts\Make-Overview.ps1
```

**重建会覆盖相同编号的原生文件、STEP 和预览。** 脚本连接已运行的 SolidWorks，不负责启动软件。批量模型的几何坐标与操作顺序在 [BatchModels.cs](scripts/BatchModels.cs) 中；终端输出 `All requested models passed.` 表示本次请求的编号通过检查。失败时会汇总 `Failures:`，并将细节追加到日志。重新建模后，CSV 文件校验值可能变化；现有 `模型清单.csv` 是本次交付快照，不由入口脚本自动更新。

原生文件以 SolidWorks 2025 保存。本项目没有验证其他版本的重运行兼容性；跨 CAD 软件查看时可先使用 STEP。

## 可复用的经验

### 1. 用强类型 COM 接口打通执行链路

通过 `Marshal.GetActiveObject("SldWorks.Application")` 获取已有实例，加载本机接口库后，在 C# 中使用 `ISldWorks`、`IModelDoc2` 等明确的接口类型。本机动态调用版本号曾遇到 `0x8002802B`，改为强类型接口后成功。

沙箱内连接曾返回 `0x800401E3`，沙箱外测试成功。因此，在受限执行环境中应检查桌面会话与访问权限；不能仅凭这个错误码判断 SolidWorks 未启动。在 Codex 中，本机桌面 COM 调用需要相应的执行权限。

### 2. 几何理解与 API 执行分别检查

先明确三维点、轮廓、面以及它们在各投影中的对应关系，再写建模步骤。API 能成功创建一个实体，只能证明这组几何能成立，不能证明它符合题图。适合把“读图假设”和“执行失败”分开记录，避免反复修改接口却没有纠正几何理解。

### 3. 放样要明确顶点对应关系

本批主要通过封闭的平面内 3D 草图、实体放样和放样切除构造多面体。截面的顶点数、绕行顺序应一致；对称或非平行截面还需要明确连接关系。

第 12 页模型曾在返回合法实体的同时发生表面扭转。增加逐顶点直线导引线后修正，说明“实体合法、体积为正”不足以替代外观检查。建模方法可灵活选择，不必为了模仿人工步骤而限制为拉伸或切除。

### 4. 减少语言、单位和文档状态造成的歧义

- API 长度使用米，体积使用立方米：毫米坐标除以 1000，体积转换成 mm³ 乘以 `1e9`。
- 选择基准面时优先使用特征对象，避免依赖 `Front Plane` 等本地化名称；旧 VBA 就曾在选面环节失败。
- STEP 导出前按完整路径激活目标零件，避免导出了另一个活动文档。
- 回读检查采用唯一临时文件名，并给导入文档单独命名，避免与原生文档重名。
- 只关闭本次创建或明确检查过的文档，不按名称通配清理用户未保存的工作。
- 中文脚本内容需正确保存编码；Windows PowerShell 读取无 BOM 的 UTF-8 曾导致中文路径乱码。本批 C# 对中文文件名前缀使用 Unicode 转义。

### 5. 保留检查记录与容易理解的名称

推荐的闭环是：**创建特征 → 重建 → 检查实体和体积 → 查看多视图 → 保存 → 回读复核**。通过 API 可以主动查询状态和导出模型图片，但这不等于持续实时观看软件窗口。

简单模型采用“零件1”“零件2”等文件名，草图和特征保留 SolidWorks 默认中文名称，方便接收者继续修改。复杂结构确有需要时，再使用简短中文说明。

## 适用范围与限制

- 原图没有尺寸，模型的整体大小、槽宽、斜率等按图估算；目前未完成全部投影线段的自动精确配准。
- 第 18、19 页涉及通孔、斜底面及截切，应优先结合课件复核几何解释。
- 模型保留可编辑特征树，但草图主要由坐标给定，尚未整理成尺寸驱动、完全约束的参数化模板。
- 本实验验证的是这批平面立体，不代表任意机械零件、装配或工程图都能可靠自动生成。
- 失败的外部手写 STEP 导入路线仅作留档，不是当前建模流程。最终 STEP 是由成功建立的 SolidWorks 原生模型导出。
